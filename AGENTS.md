# AGENTS.md — EFT SIP Calculator

Этот файл содержит постоянные правила работы Codex с репозиторием
`svc4p7vc8y-beep/EFT-SIP-Calculator`.

## Назначение проекта

EFT SIP Calculator — калькулятор домов и домокомплектов из SIP-панелей с
редактором плана, расчётом материалов, работ, раскроя, крепежа и итоговой сметы.
Основной интерфейс — React-приложение. `legacy-v45.html` и другие legacy-файлы
являются резервными версиями и не должны становиться основной точкой разработки.

## Главные правила

- Не менять геометрию плана, размеры помещений, проёмы и конструктив без прямого
  указания пользователя.
- Не менять действующие цены, коэффициенты, нормы расхода и формулы молча.
  Сначала показать источник, старое значение, предлагаемое значение и влияние на
  смету.
- Не переносить монтажную рекомендацию в автоматическую формулу без технической
  проверки и согласования пользователя.
- Сохранять возможность ручного ввода и проектных переопределений.
- По умолчанию сохранять светлую тему и адаптивность для работы с iPad.
- Не удалять старые функции и данные ради упрощения интерфейса.
- Не публиковать изменения и не отправлять их в `main` без прямого разрешения.

## Принятые данные EFT

- Базовый формат SIP-панели: 2500 × 1250 мм.
- Базовая сетка раскладки: 625 мм.
- Пол и потолок раскладываются в шахматном порядке, если пользователь не выбрал
  другой вариант.
- Применяемые семейства толщины готовых SIP-панелей: 124, 174 и 224 мм.
- Базовый внутренний термобрус: 145 × 90 мм; торцевая/лобовая доска — 145 × 45
  или фактический профиль, выбранный в проекте.
- Стандартный запас материалов по умолчанию — 10%, если для конкретной позиции
  не установлено отдельное правило.
- Длина и ширина плиты, сердцевины и панели должны оставаться редактируемыми.
- Любые данные из книги, прайса или сметы считать источником для сверки, а не
  автоматической заменой действующей модели.

Если эти ориентиры расходятся с сохранёнными параметрами конкретного проекта,
приоритет имеют явно сохранённые значения проекта.

## Книга по технологии SIP

Источник: «Как собрать СИП-дом самому? Руководство по строительству домов по
технологии SIP», А. С. Курманов, К. С. Курманов, Е. В. Курманова.

- Исходный PDF — скан: 186 PDF-страниц, 183 страницы печатной нумерации.
- Не добавлять исходный PDF в публичный репозиторий: файл большой и может быть
  защищён авторским правом.
- Структурированная карта книги хранится в
  `src/react/data/sip-guide.js`.
- Экран справочника находится в
  `src/react/screens/SipGuideScreen.jsx`.
- В пользовательском интерфейсе всегда указывать печатную страницу источника.
- Разделять сведения на:
  - справочные монтажные рекомендации;
  - кандидаты в расчётные нормы;
  - подтверждённые формулы.
- При извлечении нормы записывать: раздел, печатную страницу, формулировку своими
  словами, единицу измерения, область применения, ограничения и отличие от
  текущей формулы.

## Архитектура

- `src/react/app/` — оболочка и навигация.
- `src/react/screens/` — экраны приложения.
- `src/react/calculations/` — расчётное ядро.
- `src/react/state/` — модель проекта, миграции и история.
- `src/react/data/` — встроенные справочные и каталожные данные.
- `src/react/export/` — экспорт смет.
- `tests/` — регрессионные тесты.
- `public/` — PWA-ресурсы и логотип EFT.

Тяжёлые экраны подключать через `lazy()`. Статические справочники хранить отдельно
от расчётного ядра. Не дублировать одну формулу в нескольких экранах.

## Порядок изменения расчётов

1. Найти действующую формулу и все её потребители.
2. Зафиксировать текущее значение и тестовый пример.
3. Указать источник нового правила.
4. Сравнить старый и новый результат.
5. Добавить настройку или миграцию, если меняется формат проекта.
6. Добавить регрессионный тест.
7. Запустить весь комплект тестов и производственную сборку.
8. В итоговом сообщении перечислить изменённые количества и влияние на смету.

## Проверка перед завершением

```bash
npm ci
npm test
npm run build
```

Дополнительно проверить:

- светлую тему;
- мобильную ширину около 390–430 px и планшетную ширину около 768–1024 px;
- отсутствие переполнения таблиц и боковых панелей;
- сохранение и повторное открытие `.eft.json`;
- работу отмены и повтора;
- сохранение старых проектов после миграции;
- отсутствие ошибок и предупреждений приложения в консоли.

Если визуальный браузер недоступен, прямо указать, что сборка и тесты пройдены,
но визуальная проверка не выполнена.

## Code Review Rules

### Расчёты и смета

- Проверять округление закупаемого материала вверх и сохранение единиц измерения.
- Проверять, не посчитан ли один материал дважды в разных разделах.
- Проверять совпадение `catalogId` с прайсом и отсутствие строк без цены.
- Проверять, что ручные проектные правки не меняют общий прайс-лист.

### Совместимость

- Не ломать импорт старых `.eft.json`.
- Для новых полей добавлять безопасные значения по умолчанию и миграцию.
- Не менять существующие идентификаторы каталога без миграции.

### Интерфейс

- Не ухудшать мобильную работу и сенсорное управление.
- Не прятать важные расчётные параметры без понятного пути к ним.
- Все новые нормы должны показывать источник или пояснение.
