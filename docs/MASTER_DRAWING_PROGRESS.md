## Матрица / уже реализованные этапы

1. I1: BUILDING_AUDIT в building-model.js: поле → сущность → лист → ведомость → тест.
   Реальные производственные ID/марки сохраняются, instances пакета различаются.
2. I2: documentation.building: оси X/Y, ±0.000, проектные отметки этажей, допуск
   геометрического сравнения, линии/глубина разрезов, catalogMappings. Старый файл
   получает НЕподтверждённые пустые параметры, неизвестные поля документации сохраняются.
   Отметки сравниваются с productionLevels, конфликт не двигает этажи.
3. I3: building-mesh использует beamFrame, flat и реальные торцы стропил WebGL.
   production-views теперь использует те же mesh-адаптеры. building-model получает
   панели, реальные отверстия, каркас и опоры из productionScene, без новых закупок.
   drawing-projection: четыре ортогональных фасада, планы сечения этажа, разрезы
   реальных замкнутых призм; XOR сохраняет сквозные отверстия. drawing-visibility
   скрывает поверхности по локальной глубине в каждой зоне перекрытия, не среднему Z.
   Координаты visibility округлены до 0,0001 мм для устойчивости polygon-clipping;
   это не строительный допуск. Ошибка clipping оставляет диагностический вид и блокер.
4. I4: ArchitecturalReleasePages добавляет реальные фасады, планы с осями, разрезы
   к обоим вариантам альбома. Масштаб отдельных видов выбирается из физических
   размеров миллиметров, не CSS-зум; подпись масштаба у каждого вида. Требует PDF QA.
5. I5: существующие КД/ПР/МН сохранены. Новые виды связаны с sourceId/hostId;
   выбор детали открывает исходную конструкцию. foundationGeometry — общая
   геометрия опор WebGL и АР; блок берёт существующие размеры, неизвестные сваи
   остаются маркерами осей. Новые размеры свай задаются пользователем, не из цены.
6. I6: family purchaseRows → явный catalogId + подтверждённый пересчёт. Один
   catalogId сравнивается с суммой требований всех назначенных семейств: нельзя
   один запас использовать дважды. Недостача не закрывается примечанием.
   Выпуск содержит building/views/mapping, building.json и production-catalog.csv
   с общим SHA256, без живого пересчёта архивов. AR_AXES / AR_VIEWS /
   CATALOG_MAPPING теперь зависят от данных, а не являются безусловными заглушками.

- АР-Ф1/Ф2, АР-Пn, АР-Рn включены в компактный и полный альбомы. Линии и стрелки
  разрезов есть на плане; высота горизонтального сечения редактируется.

  не превращаются в подтверждения изменённого проекта автоматически.

  существующие тесты Г-контуров/террас. Реальный 08451 даёт четыре фасада без
  ошибок скрытия: 141 панель / 561 деревянная деталь / 2 094 104,75 ₽ на контрольном
  встроенном прайсе. Размеры/сохранённые данные/смета до и после модели одинаковы.
- PDF A4/A3: по 21 листу в контрольном доме 3×6; без лишних пустых страниц и
  переполнения. Физический масштаб проверен по X/Y с погрешностью <0,1%.
  Устранён max-height, который сжимал SVG и искажал масштаб. A4-листы отрендерены

- Исправлен фильтр 3D компактного альбома: стропила, прогоны, обрешётка и
  контробрешётка больше не исчезают с общего вида и листа кровли.
- Явный коэффициент соответствия каталогу имеет приоритет над 1 при одинаковых

- Старый manual-match больше не тупик: полное подтверждённое соответствие

  невыбранные оси/отметки/разрезы и отсутствие рабочих узлов остаются блокерами.
