# Переезд на Timeweb

Рабочая схема: публичный сайт и анкета — `eftsip.ru`/`www.eftsip.ru`,
калькулятор — `calc.eftsip.ru`, CRM — `crm.eftsip.ru`.
Почтовые ящики остаются у существующего провайдера. Не заменять MX и почтовые TXT
значениями по умолчанию Timeweb.

## Размещение

| Приложение | Каталог на Timeweb | База |
| --- | --- | --- |
| Сайт и анкета | `~/eft-site/public_html` | API калькулятора |
| Калькулятор и общий API | `~/public_html` | `cv537999_calc` |
| CRM | `~/eft-crm/public_html` | `cv537999_crm` |

Сайт собирать с `VITE_EFT_API_URL=https://calc.eftsip.ru/api/api.php` командой
`npm run build:public`. В публичном каталоге не создавать вторую копию базы или
конфигурации калькулятора. Для совместимости старых ссылок разместить
`server/timeweb/public-api-redirect.php` как `api/api.php` сайта: ответ 307
сохраняет метод, тело и строку запроса, OPTIONS обрабатывается до перенаправления.
`server/timeweb/public-site.htaccess` размещать как `.htaccess`: он выбирает
`index.html`, а не стартовую заглушку Timeweb `index.htm`.

Калькулятор собирать с `VITE_TEAM_ENABLED=true`,
`VITE_EFT_API_URL=/api/api.php`; `react.html` копировать в `index.html`.
Не включать `VITE_EFT_STANDALONE` в основной серверной версии.

Настоящие пароли, `config.local.php`, `mail.local.php`, вложения и загруженные
файлы не включать в публичный репозиторий или архив обновления.
Не удалять серверные файлы при публикации. Не перезаписывать действующие базы
Timeweb дампом Beget: новые проекты и сотрудники уже работают на Timeweb.

## Проверка переключения

1. Сохранить полную исходную DNS-зону и резервные копии баз/вложений.
2. Привязать все имена к соответствующим каталогам, проверить HTTP на IP Timeweb.
3. Изменить веб-записи, сохранив почтовые записи. Проверять отдельно результат
   в панели, авторитетные DNS и публичные резолверы.
4. Выпустить бесплатные SSL без дополнительной платной настройки; после проверки
   HTTPS включить перенаправление на HTTPS.
5. Проверить вход, сохранение/открытие проекта, загрузку/скачивание файла,
   поступление анкеты, файлы калькулятора в CRM и почтовые интеграции.
6. Включить резервные копии и автоматическую публикацию на новый хостинг.

У тестового аккаунта ограничены Cron и исходящие почтовые порты.
Для полноценных почтовых и фоновых функций потребуется оплата хостинга и
восстановление конфигураций интеграций. Старые базы и файлы Beget пока не считать
перенесёнными без проверки их импорта и сверки с новыми записями.

Проверки подготовленной версии: 1239 тестов Node пройдены; обе сборки завершены.
PHP-маршрут проверен HTTP-запросами: POST с query получает 307 на фиксированный
адрес калькулятора, OPTIONS разрешённого origin — 204, чужой origin — 403.
На Timeweb проверены HTTP-ответы сайта и анкеты (200), редирект API (307),
отдельно правильные приложения по Host калькулятора и CRM. Эти проверки не
заменяют проверку публичного DNS, HTTPS, авторизации и сквозной отправки анкеты.
