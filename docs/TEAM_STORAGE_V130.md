# EFT SIP Calculator v130: общая работа и анкеты

## Схема работы

1. `https://eftsip.ru` — публичный сайт. Он не содержит сборку внутреннего калькулятора.
2. `https://eftsip.ru/EFT_client_questionnaire.html` — публичная анкета. После отправки она получает номер вида `EFT-...` и записывается в MySQL.
3. `https://calc.eftsip.ru` — внутренний калькулятор. Серверная Basic Auth остаётся первым рубежом, затем каждый сотрудник входит под своим логином.
4. В разделе «Общие проекты» сотрудник видит проекты, входящие анкеты и, для администратора, учётные записи сотрудников.
5. Импорт анкеты создаёт проект-черновик. Геометрия помещений и расположение проёмов требуют проверки менеджером.

## Что хранится

- пользователи и роли `admin`, `manager`, `estimator`, `viewer`;
- полные JSON-проекты и текущая ревизия;
- контрольные версии проектов и автор сохранения;
- анкеты и их статусы;
- общая библиотека планов и пользовательская библиотека знаний;
- журнал ключевых действий для дальнейшего подключения CRM.

Локальное автосохранение не удалено: оно служит аварийной копией конкретного браузера. Основным источником общего проекта является MySQL.

## Защита от потери данных

- сервер не принимает сохранение поверх более новой ревизии;
- контрольная версия создаётся при явном сохранении и не реже одного раза в пять минут активной работы;
- workflow загружает файлы без `--delete` и не заменяет `.htaccess`, `.htpasswd` и `api/config.local.php`;
- Beget выполняет собственные резервные копии, но перед внедрением CRM рекомендуется добавить ежедневный выгруженный дамп MySQL во второе хранилище.

## Первичная настройка на Beget

1. Создать отдельную базу и пользователя MySQL.
2. Скопировать `server/beget-api/config.example.php` в `/api/config.local.php` на сервере и заполнить реквизиты БД, два разных случайных секрета и разрешённые origins.
3. Открыть по HTTPS `/api/install.php`, ввести одноразовый setup token и создать первого администратора с паролем не короче 12 символов.
4. После успешной установки `install.php` перестаёт показывать форму, потому что таблица пользователей уже непустая.
5. Создать отдельный ограниченный SFTP-аккаунт для каталога основного сайта и GitHub Secrets `BEGET_SITE_SSH_USER`, `BEGET_SITE_SSH_PASSWORD`, `BEGET_SITE_DEPLOY_PATH`.

Секреты и `config.local.php` запрещено добавлять в Git. Клиентские персональные данные также не должны попадать в логи GitHub Actions.
