# Автоматическая публикация на Beget

Workflow `.github/workflows/beget.yml` запускается после каждого push в ветку
`main`, выполняет тесты, собирает приложение и копирует содержимое `dist` на
Beget по SFTP/SSH.

Публикация не удаляет существующие файлы на сервере. Файлы `.htaccess` и
`.htpasswd` исключены из копирования, поэтому парольная защита сайта сохраняется.

## Подготовка Beget

1. В панели Beget включить SSH-доступ.
2. Создать отдельный FTP/SSH-аккаунт, ограниченный каталогом калькулятора.
3. Узнать имя сервера в разделе технической информации. Обычно оно имеет вид
   `логин.beget.tech`; порт SFTP/SSH — `22`.
4. Проверить путь от домашнего каталога SSH-пользователя до `public_html` сайта
   `calc.eftsip.ru`.

Для аккаунта, ограниченного непосредственно каталогом `public_html`, обычно
используется `BEGET_DEPLOY_PATH=/`. Перед загрузкой workflow проверяет, что по
этому пути уже существуют `.htaccess` и `.htpasswd`. Если путь указан неверно,
публикация остановится до копирования файлов.

## Secrets репозитория GitHub

В `Settings → Secrets and variables → Actions` создать следующие Repository
secrets:

- `BEGET_SSH_HOST` — имя сервера Beget без `https://`;
- `BEGET_SSH_USER` — имя отдельного SSH-пользователя;
- `BEGET_SSH_PASSWORD` — пароль отдельного SSH-пользователя;
- `BEGET_SSH_KNOWN_HOSTS` — строка публичного host key сервера Beget;
- `BEGET_DEPLOY_PATH` — путь к каталогу `public_html` калькулятора.

Закрытый ключ и пароли нельзя добавлять в файлы репозитория.

## Запуск и проверка

После добавления secrets workflow можно запустить вручную в разделе
`Actions → Deploy EFT calculator to Beget → Run workflow`. Дальше он будет
запускаться автоматически после каждого push в `main`.

Последний шаг ожидает код `401` от `https://calc.eftsip.ru`: это подтверждает,
что сайт доступен и парольная защита продолжает работать.
