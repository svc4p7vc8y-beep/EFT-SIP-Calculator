# Автоматическая публикация на Beget

Workflow `.github/workflows/beget.yml` запускается после каждого push в ветку
`main` с изменениями калькулятора или самого workflow. Сначала проверяет SSH-доступ,
затем выполняет тесты, собирает приложение и копирует содержимое `dist` на
Beget по SFTP/SSH.

Публикация не удаляет существующие файлы на сервере. Файлы `.htaccess` и
`.htpasswd` исключены из копирования, поэтому настройки доступа сайта сохраняются.

## Подготовка Beget

1. В панели Beget включить SSH-доступ.
2. Создать отдельный FTP/SSH-аккаунт, ограниченный каталогом калькулятора.
3. Узнать имя сервера в разделе технической информации. Обычно оно имеет вид
   `логин.beget.tech`; порт SFTP/SSH — `22`.
4. Проверить путь от домашнего каталога SSH-пользователя до `public_html` сайта
   `calc.eftsip.ru`.

Для аккаунта, ограниченного непосредственно каталогом `public_html`, обычно
используется `BEGET_DEPLOY_PATH=.`. Точка обозначает домашнюю директорию
ограниченного SSH-аккаунта. Перед загрузкой workflow проверяет, что по
этому пути уже существует `.htaccess` и каталог доступен для записи. Файлы `.htaccess` и `.htpasswd`
в любом случае исключены из копирования. Если путь указан неверно,
публикация остановится до копирования файлов.

## Secrets репозитория GitHub

В `Settings → Secrets and variables → Actions` создать следующие Repository
secrets:

- `BEGET_SSH_HOST` — имя сервера Beget без `https://`;
- `BEGET_SSH_USER` — имя отдельного SSH-пользователя;
- `BEGET_SSH_PASSWORD` — пароль отдельного SSH-пользователя;
- `BEGET_SSH_KNOWN_HOSTS` — строка публичного host key сервера Beget;
- `BEGET_DEPLOY_PATH` — путь к каталогу `public_html` калькулятора.

Закрытый ключ и пароли нельзя добавлять в файлы репозитория.

## Запуск и проверка

После добавления secrets workflow можно запустить вручную в разделе
`Actions → Deploy EFT calculator to Beget → Run workflow`. Дальше он будет
запускаться автоматически после каждого push в `main`.

Последний шаг проверяет страницу React-калькулятора на `https://calc.eftsip.ru/`
и сравнивает `build-info.json` с текущим commit SHA и номером версии. Успешная
сборка сама по себе не означает, что новая версия опубликована.

Изменения только инфраструктуры не требуют увеличивать версию приложения;
если файл версии меняется, проверка по-прежнему требует шаг ровно на единицу.

## Если публикация не работает

Ошибка `Permission denied` и код `5` в шаге проверки SSH означают, что сервер
отклонил данные входа. Проверьте пару `BEGET_SSH_USER` / `BEGET_SSH_PASSWORD`
и обновите соответствующие Actions secrets. Нужны данные SSH-аккаунта,
а не обязательно пароль панели управления Beget. Вход в Beget через браузер
не обновляет секреты GitHub. Пароли не нужно вставлять в код, issue или чат.

После исправления secrets повторите неуспешное задание (`Re-run failed jobs`)
или запустите workflow вручную. При ошибках host key нужно сверить публичный
ключ с Beget и обновить `BEGET_SSH_KNOWN_HOSTS`; проверку ключа не отключать.
