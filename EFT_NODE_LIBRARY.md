# Библиотека строительных узлов EFT

`EFT_NODE_LIBRARY.json` — единый, независимый от производителя справочник узлов для калькулятора EFT. Его можно применять к планам `.eft-plan.json` и будущему экспорту из SketchUp. Товарный бренд и цена выбираются только после того, как узел определил технический тип и размер крепежа.

## Единицы и статус нормы

- геометрическая длина — метры;
- размеры крепежа и отступы — миллиметры;
- количество — штуки;
- `requiresEngineeringReview: false` означает, что расчётная схема опирается на проиндексированный источник или принятую норму EFT;
- `requiresEngineeringReview: true` означает, что геометрия узла может быть посчитана, но типоразмер или норма не должны считаться утверждёнными.

Неизвестная норма не заменяется предположением. Такой узел сохраняется в отчёте с нулевым или проектным количеством и предупреждением.

## Поля узла

| Поле | Назначение |
|---|---|
| `code` | Стабильный уникальный код узла. Не переименовывать без миграции. |
| `name`, `section`, `marker` | Название, раздел ведомости и буква маркера на плане. |
| `elements` | Универсальные имена соединяемых конструктивных элементов. |
| `fasteners[]` | Один или несколько вариантов технического крепежа. |
| `type`, `size` | Тип и размер без привязки к бренду. Значения `BY_SIP_THICKNESS` и `NEXT_SIZE_BY_SIP_THICKNESS` разрешаются по толщине панели. |
| `quantityMode` | Способ расчёта: по длине и шагу, по периметру, на панель или на узел. |
| `stepFormulaKey`, `qtyFormulaKey`, `rowsFormulaKey` | Ключ редактируемой проектной нормы в `settings.formulas`. |
| `rows`, `edgeOffsetMm`, `staggered` | Ряды, отступ и шахматность. `null` означает, что подтверждённых данных нет. |
| `washer`, `metalConnector` | Требование шайбы или металлического соединителя. |
| `packSize` | Размер упаковки, если он задан; по умолчанию `null`. |
| `alternatives` | Технически допустимые альтернативы, не товарные бренды. |
| `source` | Тип источника, ключ раздела индекса, страницы и пояснение. |

## Реализованные группы

- SIP: шпонка/термобрус, торцевая доска и опорный крепёж панели;
- стены: стартовая и верхняя доски, стартовая доска через SIP 224, наружный угол, соединение стен и Т-узел;
- проёмы: окно и дверь;
- перекрытия: пол, потолок, стена–межэтажное перекрытие и стена–потолок;
- кровля: SIP-кровля, мауэрлат, стропильные опоры, конёк, связи, обрешётка и контробрешётка;
- фундамент и пристройки: обвязка свай, терраса, лаги террасы и крыльцо.

## Подбор длины для SIP

Для обычных стеновых узлов размер определяется реальной толщиной SIP через проектные таблицы `sipStructuralScrew*`. Для опорных контуров используется следующий подтверждённый размер через `sipSupportScrew*`. Узел `SIP_START_BOARD_THROUGH_224` закреплён отдельно: доска 45 мм + SIP 224 мм + требуемый заход 50 мм дают минимум 319 мм, поэтому применяется 8×320. Более короткий ручной вариант вызывает ошибку модели.

## Индекс книги

Машиночитаемый индекс находится в `src/react/data/eft-book-index.js`. Сейчас подтверждены диапазоны:

- шпонки, термобрус и торцевые доски — печатные страницы 12, 34, 60, 78, 143–144;
- стены и обвязки — 56, 59–60, 68–78;
- полы, потолки и межэтажные опоры — 34–64;
- SIP-кровля — 134–144, 161–164.

Фундамент, точное усиление проёмов, каркасная кровля, обрешётка, террасы, навесы и крыльцо отмечены `requires-indexing`. Пока соответствующий источник не подтверждён, их нормы остаются на инженерной проверке.

## Расширение библиотеки

Новый узел получает новый стабильный `code`, источник и регрессионный тест. Если точная норма отсутствует, нужно оставить пустой список `fasteners` либо неполный проектный вариант и установить `requiresEngineeringReview: true`. Нельзя копировать норму соседнего узла только из-за похожей геометрии.
