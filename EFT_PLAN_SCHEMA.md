# Формат проекта EFT House Plan

Документ описывает переносимый файл `*.eft-plan.json`. Текущая версия — `schemaVersion: 4`. Файлы версии 3 продолжают открываться: при импорте отсутствующие `construction` и `nodes` создаются пустыми, после чего узлы можно восстановить кнопкой «Рассчитать узлы и метизы».

## Корневая структура

```json
{
  "format": "eft-house-plan",
  "schemaVersion": 4,
  "appVersion": 125,
  "savedAt": "2026-09-10T12:00:00.000Z",
  "sourceProject": "0001576",
  "plan": {},
  "floors": 1,
  "upperFloors": [],
  "construction": {},
  "nodes": [],
  "settings": {},
  "services": {}
}
```

`format` и `schemaVersion` обязательны для однозначного распознавания. `floors` — 1 или 2. `settings` и `services` переносят расчётные параметры проекта, но не изменяют общий прайс-лист.

## Координаты и единицы

- начало координат плана: левый верхний угол дома;
- `x` растёт вправо, `y` — вниз;
- координаты, длины, ширины, высоты и шаги конструкций хранятся в метрах;
- толщины SIP в расчётных настройках хранятся в миллиметрах, а `plan.wallThickness` и `partitionThickness` — в метрах;
- углы кровли — градусы;
- размеры крепежа — миллиметры;
- количество материалов — в единице, указанной строкой сметы.

## `plan`

| Поле | Правило |
|---|---|
| `house` | Габарит `{ "w": число, "h": число }`, оба значения больше нуля. |
| `wallHeight` | Высота стен. |
| `wallThickness`, `partitionThickness` | Толщины наружной стены и перегородки в метрах. |
| `rooms[]` | Помещения. Прямоугольник задаётся `x,y,w,h`; многоугольник — `points:[{x,y}]`. `include:false` исключает помещение. |
| `walls[]` | Явные отрезки стен с устойчивым `id`, началом/концом либо принятой редактором геометрией. Не менять форму без запроса пользователя. |
| `wallGaps[]` | Разрывы стен. |
| `openings[]` | Двери и окна: `id`, `type` (`door`/`window`), `x`, `y`, `orientation` (`h`/`v`), `width`, `height`, `outer`. |
| `platforms[]` | Террасы и крыльца. `kind`: `terrace` или `porch`; геометрия `x,y,w,h`; `include` управляет расчётом. |
| `pileRows[]` | Линии рядов свай: `x1,y1,x2,y2,count,group`. |
| `piles[]` | Отдельные сваи с `id,x,y,group`; не дублировать сваи рядов. |
| `bindingLines[]` | Линии обвязки с координатами начала и конца. |
| `excludedPiles[]` | Идентификаторы/координаты исключённых свай. |
| `floorOpening` | Проём перекрытия, если он существует. |
| `dimensions[]` | Пользовательские размерные линии; на расчёт геометрии не влияют. |

Все сущности должны иметь предсказуемый уникальный `id`: например `room-1`, `wall-outer-north`, `window-kitchen-1`. При редактировании существующего объекта его `id` сохраняется.

## Этажи

`plan` содержит первый этаж. `upperFloors[]` содержит нормализованные планы следующих этажей в том же формате. Число реально используемых планов согласуется с `floors`. Отсутствующий второй план создаётся миграцией безопасно, без изменения первого этажа.

## Настройки SIP, кровли и фундамента

Значения находятся в `settings`:

- `sip`: типы и толщины панелей пола, стен, перегородок, потолка; раскрой и `consumablesMode` (`node` приоритетен, `quick` — резервный режим);
- `roof`: тип кровли, уклон, ориентация, свесы, фронтоны, SIP- или каркасная конструкция, стропила, мауэрлат, обрешётка и контробрешётка;
- `piles`: тип, параметры и правила свайного поля/обвязки;
- `formulas`: редактируемые нормы и шаги. Не заменять их молча;
- `nodeFasteners`: общий запас, упаковки и дата последней фиксации расчёта;
- остальные разделы (`delivery`, `engineering`, `internal`, `external`, `print`, `links`, `priceAdjustments`) сохраняются без потерь.

## `construction`

Явный конструктивный снимок содержит массивы:

```json
{
  "floorPanels": [],
  "wallPanels": [],
  "ceilingPanels": [],
  "splines": [],
  "starterBoards": [],
  "topBoards": [],
  "edgeBoards": [],
  "rafters": [],
  "mauerlat": [],
  "lath": [],
  "counterLath": []
}
```

Автоматические элементы имеют `source: "auto"`; пользовательские — `source: "manual"`. Типовые поля: `id`, `floor`, `length`, `area`, `panelThickness`, `step` и геометрия. Снимок можно пересоздать из плана; ручные проектные данные нельзя удалять при миграции.

## `nodes[]`

Минимальный узел:

```json
{
  "id": "node-1-corner-0",
  "type": "SIP_WALL_CORNER",
  "x": 0,
  "y": 0,
  "floor": 1,
  "length": 2.5,
  "source": "auto",
  "enabled": true
}
```

Допустимые типы перечислены в `EFT_NODE_LIBRARY.json`. В узле могут храниться переопределения:

- `calculatedQtyOverride` — ручное расчётное количество;
- `spacing` — ручной шаг;
- `reservePercent` — индивидуальный запас;
- `packSize` — размер упаковки;
- `fastenerOverride` — технический тип/размер крепежа;
- `requiresEngineeringReview` — принудительная инженерная проверка.

Автоматический `id` детерминирован геометрическим назначением, чтобы переопределение применялось после повторного расчёта. `enabled:false` исключает узел из ведомости, но не удаляет его историю. Ручной узел должен иметь `source:"manual"`.

## Расчёт и закупка

В отчёте по узлам разделяются:

- `calculatedQty` — математическая потребность;
- `reservePercent` — запас;
- `withReserve = ceil(calculatedQty × (1 + reservePercent / 100))`;
- `purchasePacks = ceil(withReserve / packSize)`, если упаковка известна;
- `purchaseQty = purchasePacks × packSize`, иначе равно `withReserve`.

Позиции сводного заказа объединяются по техническому типу и размеру, а не по производителю.

## Правила безопасного редактирования ChatGPT

1. Сохранять `format`, повышать версию только при документированной миграции.
2. Не менять существующие координаты, размеры, цены, формулы и идентификаторы без явного запроса.
3. Сохранять неизвестные поля — это обеспечивает совместимость с новыми версиями.
4. Для новых объектов применять уникальные понятные ID и метры в геометрии.
5. Не записывать неподтверждённую норму как точную: использовать `requiresEngineeringReview:true`.
6. После редактирования проверить положительные размеры дома, ссылки на этажи, уникальность ID и импорт файла в калькулятор.

## SketchUp

Будущий экспорт может отдавать `{ "elements": [], "nodes": [] }`. Элементы используют универсальные имена (`SIP_WALL_224`, `SIP_FLOOR_224`, `THERMOBRUS`, `START_BOARD_45`, `RAFTER_50x150`, `MAUERLAT`), а `nodes[].type` — те же коды `EFT_NODE_LIBRARY`. Так один набор норм применяется без привязки к редактору геометрии.
