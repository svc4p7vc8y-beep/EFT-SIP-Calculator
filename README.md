# ЭФТ — калькулятор СИП-дома

Веб-приложение для планировки дома, расчёта свай, СИП-панелей, кровли, террас, проёмов, крепежа, работ и итоговой сметы.

## Быстрый запуск

```powershell
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://127.0.0.1:5173/`). Не открывайте `index.html` двойным щелчком: рабочее приложение должно запускаться через локальный сервер или GitHub Pages.

Проверка перед публикацией:

```powershell
npm test
npm run build
npm run preview
```

## Сохранение проекта

Кнопка с дискетой создаёт переносимый файл `Проект_XXXX_Заказчик_Дата.eft.json`. В нём находятся:

- карточка проекта и параметры;
- редактируемый план, комнаты, стены, проёмы, пристройки, сваи и обвязка;
- библиотека пользовательских эскизов;
- результаты калькуляторов и смета;
- действующий прайс материалов и работ;
- выбранный режим цен.

Кнопка с папкой открывает `.eft.json`. Старые проекты, сохранённые внутри HTML, также поддерживаются для переноса данных.

Автосохранение выполняется в `localStorage` и дополнительно зеркалируется в IndexedDB. Оно помогает после аварийного закрытия, но не заменяет файл проекта.

## Прайс-лист

Раздел «Единый прайс-лист» содержит две независимые таблицы:

- материалы, оборудование и комплектующие;
- строительные и монтажные работы.

Изменение цены обновляет калькуляторы и смету. Прайс сохраняется тремя способами:

1. Внутри каждого файла проекта `.eft.json` — проект откроется с теми ценами, по которым считался.
2. В браузере — текущий рабочий каталог восстанавливается при следующем запуске.
3. Отдельным файлом `Прайс-лист_ЭФТ_Дата.eft-price.json` — для переноса общей базы цен между компьютерами.

Кнопки раздела:

- **Сохранить прайс** — переносимый редактируемый каталог;
- **Открыть прайс** — заменить текущий каталог и пересчитать калькуляторы;
- **Прайс в Excel** — таблица для просмотра, печати и обмена; Excel не является основным форматом обратного импорта.

Перед массовым изменением цен рекомендуется сохранить отдельную копию прайса. При открытии проекта его прайс заменяет текущий каталог, чтобы сохранить воспроизводимость сметы.

## Структура

```text
index.html                    текущий рабочий интерфейс v43
src/bootstrap.js              подключение хранилища и PWA
src/storage/                  схема проекта, JSON и IndexedDB
public/manifest.webmanifest   установка как приложения
public/sw.js                  офлайн-кэш
tests/                        тесты форматов проекта и прайса
legacy/                       контрольная монолитная версия v43
.github/workflows/pages.yml   публикация GitHub Pages
```

Редактор и расчёты пока остаются внутри `index.html`, чтобы не сломать рабочую v43. Их следует переносить в `src/planner/` и `src/calculators/` небольшими проверяемыми этапами.

## GitHub Pages

1. Создайте на GitHub приватный или публичный пустой репозиторий.
2. Добавьте его как `origin` и отправьте ветку `main`.
3. В настройках репозитория откройте **Settings → Pages**.
4. В качестве Source выберите **GitHub Actions**.

Workflow автоматически запускает тесты, собирает приложение и публикует папку `dist`.

## Мобильная версия

Текущий этап уже является PWA: после публикации приложение можно установить из браузера на Android или компьютер. Следующий этап — адаптация редактора под сенсорное управление. Для выпуска APK/iOS без переписывания расчётного ядра можно подключить Capacitor.
